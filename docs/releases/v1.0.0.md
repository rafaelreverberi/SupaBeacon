# SupaBeacon 1.0.0

First public release of SupaBeacon, a self-hosted Supabase project monitor and activity manager.

- One container, persistent SQLite storage and a web dashboard with dark/light themes.
- Supabase Management OAuth with PKCE, encrypted credentials, automatic discovery and bounded scheduled heartbeats.
- Up to eight named activities per project: bounded public reads or dedicated test-account sign-in → read → local sign-out. Each has its own switch and expandable editor.
- Table/column discovery, execution details, searchable logs, backup/restore and configurable ports.
- Prebuilt native **linux/amd64** and **linux/arm64** Docker images, health checks, SBOM/provenance metadata and a source/installer archive with SHA-256 checksums.

## Install on a NUC, VPS or 64-bit ARM host

Install Docker Engine with Compose v2, Bash, OpenSSL and `ss` or `lsof`. Download and extract **SupaBeacon-v1.0.0.tar.gz**, then run:

```bash
cd SupaBeacon-1.0.0
./setup.sh --image
```

Or clone [the repository](https://github.com/rafaelreverberi/SupaBeacon) and run the same command. The installer creates a private `.env` and uses `ghcr.io/rafaelreverberi/supabeacon:1.0.0`. Docker selects your architecture. The dashboard defaults to port 8080; the wizard lets you change it. Follow the included [OAuth guide](https://github.com/rafaelreverberi/SupaBeacon/blob/v1.0.0/docs/oauth-setup.md) to register your own integration. The logo is included and available as a release download.

The image is also tagged `latest`; pin the version for controlled upgrades. `SHA256SUMS` covers the installer archive, standalone Compose file, logo and image manifest. The complete source is included; no developer configuration, accounts or database are shipped.

## Verification and limits

50 automated unit/integration tests and a Chromium browser journey cover activity isolation, migration, credential redaction, logout cleanup, configuration, administration and responsive UI. Release CI also runs these checks and starts each architecture image on a native Linux runner before publishing the combined tags.

Successful requests do **not** guarantee that Supabase will never pause a free project. Extra activities are off by default. Existing RLS and quotas apply, and an empty read response does not prove visible rows exist. See the included documentation for exact evidence and operational limits. The project is not affiliated with Supabase.
